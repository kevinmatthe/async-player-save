# 保存架构

## 线程和完成条件

服务器线程处理可变 Minecraft 对象；提交给后台的 NBT 必须是独立快照。玩家任务使用自己的单线程有界队列；世界任务使用 FAWS 2.6 原 executor，保持其 FIFO 顺序，并与原有关闭屏障兼容。

```mermaid
flowchart LR
  A[服务器线程捕获 NBT] --> B[玩家队列或 FAWS 世界队列]
  B --> C[完整写入临时文件]
  C --> D[文件 force]
  D --> E[原子发布]
  E --> F[目录 force]
  F --> G[保存 future 成功]
  G --> H[FTB 后台压缩 ZIP]
```

FTB 捕获阶段取得固定的玩家和世界 future 快照；后续保存不能覆盖该检查点中的失败。保存事件通知仍回到服务器线程，之后等待世界任务和原 FAWS 队列 marker。FTB 已完成但异常的 future 也必须调用 get 检查。

## 主要组件

| 文件 | 责任 |
|---|---|
| AsyncPlayerSave / SaveQueue | 玩家快照、顺序、有界提交、读取/手动/关服屏障 |
| BackupSave / SaveContext / FtbBackupMixin | FTB 捕获上下文和完整保存 future |
| NbtWrites | 普通流写入完整 gzip/NBT，避免每段 SYNC |
| AtomicSave | 准备和 force 临时文件、保留上一版、原子发布、目录持久化 |
| WorldSaveQueue | 每个世界目标路径的完成 future，失败持续可见及恢复 |
| WorldSaveCoordinator | 世界批次、有限重试、错误和耗时日志 |
| DimensionDataStorageMixin | 在主线程捕获 dirty SavedData，每维度一批 |
| LevelStorageMixin | 捕获并提交 level.dat，保留 level.dat_old |

世界保存通过 cancellable HEAD 注入接管两个 .dat 保存入口，FAWS 原 JAR 不变。FAWS 未安装时这些注入返回原版路径。我们不在后台读取 SavedData 或玩家实体，也不拦截全部 NbtIo 调用。

## 持久化顺序

一批文件全部准备并执行 file force，之后才开始发布。玩家和 level.dat 的前一版优先用硬链接保留；不支持硬链接时复制并 force 备份，其他链接错误直接失败。替换必须支持原子移动。所有替换完成后，目录去重并从子目录向父目录同步。

失败创建的新目录不能因下一次已经存在就跳过父项同步；待完成的目录同步状态必须跨尝试保留。后台任务只有在所需目录同步全部结束后才完成成功。

## 失败和恢复

主线程捕获失败或提交被拒绝时，SavedData 保持 dirty，并记录失败结果。后台失败时在服务器线程重新标记本批数据为 dirty。错误检查点保持失败，直到对应路径实际重新提交并成功；只保存其他文件不能清除该路径失败。

发布前 IO 错误可有限重试。开始发布以后遇到错误，当前任务报告失败并停止本次重试；玩家/level.dat 的旧版不被同一次重试循环再次旋转覆盖。后续新保存可以重试，但它代表一次新的保存操作。

FTB 失败后沿用自身的保存开关恢复流程，不创建成功 ZIP。30 秒等待超时仍然存在，已提交后台 IO 不会因为备份超时而取消。应处理磁盘空间、权限或设备故障，之后再保存/备份；补丁无法替代存储修复。

## 可靠性边界

- 批量发布不是多个文件之间的事务；途中失败可能已有部分新文件可见。
- 发布后目录同步失败，目标文件可能已经替换；这时报告失败，不声称目标仍为旧版或已可靠持久化。
- `.dat_old` 是前一次文件版本，不是整个世界的事务快照。
- 原子移动和目录 force 的支持依赖文件系统，本版本以 Linux/ZFS 环境验证；不通过非原子回退掩盖不支持。
- 文件 force 依赖内核、设备正确履行持久化语义；没有进行真实断电故障测试。
- 突然断电、强制结束进程或 OOM 仍可丢失尚在内存/队列的数据。
- 只跟踪补丁接管的玩家和世界 .dat 文件；区块 region、其他模组独立写入和 FTB 本身的压缩错误不是新增世界检查点的覆盖范围。
- 世界集中持久化和世界失败传播需要 FAWS 2.6。
- 异步不会消除磁盘耗时；快照、区块准备和保存事件仍可能消耗主线程时间。
